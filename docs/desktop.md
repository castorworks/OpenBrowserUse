# 桌面与 Chrome 扩展

[文档导航](README.md) · [服务部署](service.md) · [配置参考](configuration.md)

## 启动与退出

运行 `npm start` 或打开打包应用。默认自动连接同一用户的本机服务（支持服务使用自定义数据目录）；没有服务时由 Electron 启动后台，步骤见 [服务部署](service.md)。

| 操作 | 自带后台 | 连接已有服务 |
|---|---|---|
| 退出 Electron | 停止后台和任务，释放浏览器 | 仅断开桌面，服务和任务继续运行 |
| macOS 关闭窗口 | 应用仍运行，可从 Dock 或菜单打开 | 连接仍随应用保留 |
| Windows / Linux 关闭最后一个窗口 | 退出应用并停止自带后台 | 退出应用，独立服务继续运行 |
| 后台连接中断 | 提示退出并重新打开应用 | 自动重新订阅状态，不重发命令 |

同一个桌面实例重复启动会聚焦已有窗口。界面顶部显示连接状态；已有服务模式悬停可查看地址和退出行为。

## 模型与浏览器

在设置中配置模型，详见 [模型配置](configuration.md#模型)。已有浏览器会话需要先关闭，才能修改模型或浏览器设置。

| 浏览器模式 | 登录状态 | 适用场景 |
|---|---|---|
| 独立会话 `ephemeral` | 每个新会话重新开始 | 独立任务、服务默认模式 |
| 持久化配置 `persistent` | 保存到专用浏览器目录 | 固定网站的长期自动化 |
| Chrome 扩展 `extension` | 使用当前 Chrome 的登录状态 | 本机个人浏览器 |

持久化模式先点击“打开登录浏览器”完成手动登录，关闭登录窗口后再启动任务。专用目录同一时间只能由一个浏览器占用，目录位置见 [数据目录](configuration.md#浏览器与目录)。

## Chrome 扩展自动连接

扩展支持桌面后台和独立 Node 服务；服务与 Chrome 必须能通过本机中继通信。独立服务的配置方式见 [服务部署](service.md#本机-chrome-扩展模式)。

1. 启动桌面或独立服务。扩展清单要求 Chrome 125+。
2. 在 `chrome://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，加载仓库 `extension/` 目录。打包桌面可在设置中点击“打开 Chrome 扩展目录”。
3. 在浏览器设置中选择“Chrome 扩展”并保存；独立服务首次配置可设置 `BROWSER_MODE=extension`。
4. 扩展自动连接本机服务。点击扩展图标可查看状态，显示“已连接”后即可提交任务，无需配对。

扩展固定连接中继地址 `127.0.0.1:4318`，不是 HTTP API 的 4319 端口。服务未启动时显示“等待本机服务”，断线后自动重连；中继端口被占用时后台启动失败，不自动切换。已有独立服务时 Electron 会自动连接它，不另起后台。

中继只监听本机，并校验连接来源、Host 和 Chrome 扩展 Origin；普通网页不能连接。配对令牌不再生成或使用，标准 HTTP API 的 Bearer Token 鉴权保持不变。本机进程属于信任边界，扩展来源检查不是对本机进程的身份认证。

扩展只控制代理创建的橙色“Open Browser Use”标签组和相关弹出页，不读取、操作或关闭用户其他标签页。停止任务会关闭代理标签页并释放调试器。Chrome 顶部可能显示调试提示；取消调试会断开代理控制。截图坐标对应浏览器实际视口，窗口和侧边栏尺寸变化会改变视口。

更新项目后需要在扩展管理页重新加载扩展。协议版本或截图能力不匹配时，服务会提示重新加载。扩展尚未通过商店分发。侧边栏的“打开桌面工作台”会请求已运行且连接到该后台的桌面显示窗口，不负责安装或启动未运行的 Electron。

## 提交、续聊与排队

输入目标和网址后点击“开始执行”。普通会话在一轮回答结束后保留浏览器，可以继续发送目标；新一轮拥有独立 Run ID。点击关闭浏览器可释放会话。

“加入队列”用于独立任务：每项分配自己的 Session 和 Run，完成后自动关闭浏览器并执行下一项。已有交互会话会阻塞队列，需要关闭它或等待闲置超时。暂停、等待回答和审批不会被闲置超时跳过。

执行中可以补充指令；等待问题时通过专门的回答入口回复。“暂停 / 接管”取消当前模型请求，在浏览器动作结束后暂停；有可见浏览器窗口时可以手动操作，再继续执行。无界面浏览器不提供本地可见窗口。

## 权限与操作反馈

| 模式 | 行为 |
|---|---|
| 直接执行 `skip`（默认） | 工具直接执行，不做网站、字段或受保护网站权限拦截 |
| 逐步确认 `ask` | 需要执行操作时等待用户确认 |
| 自动审查 `auto` | 规则与审查模型判断；需确认或无法判断时交给用户 |

网站授权可保存并撤销；受保护网站默认为空，只在确认模式下生效。浏览器可访问 localhost 和内网地址；代理仍阻断已识别的本机管理接口。

画面叠加代理光标、点击波纹和拖动轨迹，只用于反馈，不接管系统鼠标，也不会被烘焙到截图中。操作记录、来源和决定保存在会话中。

## 历史、恢复与导出

历史可以搜索、分页回放并导出 JSON。当前工作区只保留最近 400 条事件用于显示，导出包含完整已保存历史和脱敏资料；检查点不包含截图。

从检查点恢复会建立新浏览器，并创建新的 Session/Run，保留原历史。它先重新观察页面，不自动重放点击、提交或旧元素引用，也不会恢复已关闭的临时登录状态。只有最后一轮检查点可通过 Run 恢复接口恢复；旧格式历史的兼容行为见 [升级与迁移](migration.md)。

“本轮结束”表示模型已回答，结果仍标为 `unverified`。取消只能停止后续操作，不能撤销已发生的网页提交。

## 数据边界

模型会接收任务、网页文字、工具结果及启用后的截图。已识别凭据会在历史和导出中脱敏，但任意自由文本、脚本输出和截图不能保证自动去除秘密。密码输入和文件操作可以由代理执行；确认模式并不保证识别所有敏感操作。

封闭 Shadow DOM 和 Canvas 页面通常需要截图与坐标操作。模型文字按回答更新，目前不逐字流式显示。
